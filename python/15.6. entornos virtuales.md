#### **¿Qué es un Entorno Virtual y por qué usarlo?**

Instalar paquetes globalmente genera conflictos de versiones entre proyectos. Un **entorno virtual** es un directorio aislado que mantiene una versión de Python y dependencias exclusivas para cada proyecto.

#### **¿Por qué uv ?**

**uv** es la herramienta moderna estándar (desarrollada en Rust) que reemplaza a `pip`, `venv` y `poetry`. Es extremadamente rápida y gestiona tanto las versiones de Python como los entornos y paquetes desde un solo comando.

---

#### **Flujo de Trabajo Principal con uv**

- **Inicializar un proyecto:** Crea el directorio de trabajo y el archivo de configuración de dependencias `pyproject.toml`.

```python
uv init mi_proyecto
cd mi_proyecto
```

- **Instalar paquetes (** **uv add** **):** Descarga la librería en el entorno aislado y la registra automáticamente en el proyecto.

```python
uv add requests python-dotenv google-genai
```

- Activar el entorno virtual:

```python
.venv/Script/Activate
```

- **Ejecutar código (** **uv run** **):** Ejecuta el script dentro del entorno virtual aislado **sin necesidad de activarlo manualmente**.

```python
uv run python main.py
```

---

#### **Manejo de Variables de Entorno ( .env )**

Para no exponer credenciales o API Keys en el código, se crea un archivo `.env` en la raíz del proyecto y se lee con la librería `python-dotenv`.

```python
import os
from dotenv import load_dotenv

load_dotenv()  # Carga las variables del archivo .env al entorno

api_key = os.getenv("API_KEY")
```
