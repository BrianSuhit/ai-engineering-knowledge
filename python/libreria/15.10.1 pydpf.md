**Qué es en criollo:** 

Es la herramienta para **abrir, leer y manipular archivos PDF desde Python en código puro**, sin depender de programas externos ni navegadores.

**Qué problema resuelve:** 

Un archivo PDF no es un archivo de texto plano: tiene fuentes embebidas, tablas, metadatos y coordenadas vectoriales de dibujo. Si intentás leer un `.pdf` con un `open("archivo.pdf")` común, solo obtenés bytes ilegibles. `pypdf` decodifica la estructura interna del documento y **extrae el texto legible página por página** para que puedas procesarlo en tus pipelines.

---

**Ejemplo mínimo de código (Tu caso en** **EcoTandil-Auditor** **):**

```python
from pypdf import PdfReader

# 1. Cargamos el archivo PDF
lector = PdfReader("data/ordenanza_pdt.pdf")

# 2. Recorremos las páginas extrayendo el texto plano
texto_completo = ""
for pagina in lector.pages:
    texto_pagina = pagina.extract_text()
    if texto_pagina:
        texto_completo += texto_pagina + "\n"

print(f"Total caracteres extraídos: {len(texto_completo)}")
```

---

**La trampa o error común:**

- **Páginas escaneadas (sin capa de texto):** Si el PDF es una foto escaneada o un plano sin texto incrustado, `pagina.extract_text()` devuelve un string vacío `""` o `None`. `pypdf` **no es un OCR**; no hace reconocimiento óptico de caracteres sobre imágenes.
- **Pérdida de orden de lectura:** En documentos con columnas paralelas o tablas complejas, `extract_text()` puede mezclar los renglones de ambas columnas en la misma línea de texto, requiriendo limpieza posterior con expresiones regulares o técnicas estructurales.

### **Los métodos y atributos que más se usan:**

- **reader.pages**: Es una lista con todas las páginas del documento.
    - Te permite saber la cantidad total: `len(reader.pages)`.
    - Te permite iterar una por una: `for page in reader.pages:`.
- **page.extract_text()**: Es el método estrella. Extrae el texto legible que hay dentro de esa página específica como un string común de Python.
- **reader.metadata**: Te devuelve un diccionario con los datos del archivo (título, autor, fecha de creación). En RAG se usa mucho para guardar metadatos en la base vectorial junto a cada chunk.
