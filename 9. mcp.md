**Qué es en criollo:**

Es el **estándar "USB-C" para conectar modelos de IA con datos y herramientas externas**. En vez de que cada framework o proveedor invente su propia forma de conectar una base de datos o una API, MCP establece un protocolo abierto basado en **Cliente-Servidor (vía JSON-RPC)**: vos programás un servidor MCP una sola vez y cualquier aplicación cliente (tu agente, Claude Desktop, Cursor, etc.) puede enchufarse a él y consumir sus herramientas y datos sin tener que escribir código de integración a medida.

**Qué problema resuelve:**

Resuelve el **problema de integración** $M \times N$ **y el acoplamiento directo** entre modelos y herramientas.

1. **Fin del código pegamento (glue code):** Si tenías **M** clientes de IA (LangChain, LlamaIndex, Claude, tu propio backend) y  ***N*** sistemas externos (Postgres, GitHub, Slack, Jira), tenías que mantener $M \times N$ adaptadores. Con MCP pasa a ser $M + N$: cada sistema expone un servidor estándar y cualquier cliente lo consume de forma universal.
2. **Aislamiento de seguridad y permisos:** Los servidores corren en procesos separados y el cliente decide explícitamente qué recursos o comandos aprueba, evitando que el LLM ejecute código arbitrario dentro de tu entorno principal.
3. **Desacoplamiento arquitectónico:** Podés actualizar la base de datos o la API externa sin tener que reescribir ni tocar la lógica interna de tus agentes.

### **Primitivas clave y pseudocódigo conceptual:**

- **Las 3 Primitivas del Servidor:**
    - **Tools (Ejecución):** Funciones invocables con efectos secundarios o cómputo (ej. `crear_ticket_jira()`, `ejecutar_query_sql()`).
    - **Resources (Lectura pasiva):** Datos estructurados o texto que funcionan como archivos de solo lectura para darle contexto al modelo (ej. `postgres://schema`, `file:///logs/hoy.txt`).
    - **Prompts (Plantillas):** Flujos y plantillas pre-aprobadas que el servidor le ofrece al cliente para guiar la interacción.
- **Mínimo pseudocódigo conceptual (Servidor MCP rápido):**

```python
from mcp.server.fastmcp import FastMCP

# 1. Instanciar el servidor
mcp = FastMCP("Servicio-Operaciones")

# 2. Exponer un Resource (solo lectura de contexto)
@mcp.resource("config://status")
def obtener_estado() -> str:
    return "Base de datos: Operativa | Mantenimiento: No"

# 3. Exponer una Tool (función invocable por el LLM)
@mcp.tool()
def reiniciar_servicio(nombre_servicio: str) -> str:
    """Reinicia un servicio específico del cluster."""
    return f"Servicio {nombre_servicio} reiniciado con éxito."

# 4. Correr sobre transporte estándar (stdio o sse)
mcp.run()

**La trampa o error común:**

Confundir **MCP con una biblioteca de agentes o creer que "le da inteligencia" al modelo**. MCP es **únicamente la cañería de transporte y comunicación**; no decide cuándo llamar a una función, no planifica tareas ni razona. 

 Otra trampa crítica de diseño es **usar Tools cuando correspondían Resources**: exponer volcados masivos de datos como si fueran herramientas activas en lugar de exponerlos como recursos de lectura, lo que provoca que el agente invoque funciones innecesarias a ciegas, sature su presupuesto de tokens y degrade el contexto de la conversación.
