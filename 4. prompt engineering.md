## **Qué es en criollo el tema:** 

Es la técnica de diseñar y estructurar las instrucciones de entrada para que el modelo devuelva exactamente lo que necesitás en formato, tono y contenido. En código no es hablarle a un chat: es estructurar la llamada desacoplando el motor (`model=`), el comportamiento estático (`system_instruction=`) y los datos variables (`input=`).

## **Qué problema resuelve:**

 Elimina el no-determinismo caótico. Sin prompt engineering riguroso, el modelo devuelve texto libre impredecible, mezcla datos con órdenes operativas, ignora reglas de negocio y rompe los parsers del backend.

### **Ejemplo mínimo de código:**

```python
# uv add google-genai para instalar el paquete

from google import genai

client = genai.Client()

datos_entrada = "Error 504 a las 14:32 UTC tras timeout de 30s en servicio auth."

interaccion = client.interactions.create(
    model="gemini-4-hydrogen",
    system_instruction="Sos un clasificador de incidentes. Si falta el servicio, respondé 'DESCONOCIDO'.",
    input=f'Extraé el incidente del registro delimitado:\n"""\n{datos_entrada}\n"""',
    generation_config={
        "thinking_level": "low"  # Modulación por API en lugar de pedir Chain-of-Thought manual
    }
)

print(interaccion.output_text)
```

## **La trampa o error común:** 

Pedirle por texto *"pensá paso a paso"* (*Chain-of-Thought* manual) creyendo que eso mejora la respuesta. En modelos con razonamiento nativo, forzar CoT en el prompt interfiere con su proceso interno y degrada el resultado; además, si no delimitás físicamente los datos (`"""`), el modelo interpreta el texto del usuario como órdenes del sistema y se desvía de la tarea.
