**Qué es en criollo:** 

Es la **modularización de capacidades agénticas bajo demanda**. En lugar de atiborrar el system prompt con cientos de reglas, procedimientos y herramientas fijas, una *Skill* empaqueta instrucciones especializadas, scripts y recursos en un módulo independiente. Funciona bajo el principio de **revelación progresiva (** **progressive disclosure** **)**: el agente solo tiene cargado en su contexto activo un índice mínimo (nombre y descripción de la habilidad); únicamente cuando la tarea lo requiere, el sistema carga en la ventana de contexto el procedimiento detallado y las herramientas asociadas para resolverla.

**Qué problema resuelve:** 

Resuelve la **saturación y degradación de la ventana de contexto (** **Context Rot** **) provocada por la sobrecarga de instrucciones y herramientas**. Ataca tres cuellos de botella críticos:

1. **Agotamiento de la atención:** Evita que el agente se vuelva torpe o alucine al intentar recordar decenas de manuales de procedimientos y esquemas de funciones simultáneos.
2. **Desperdicio de tokens y latencia:** Elimina el costo de reenviar cientos de líneas de documentación en tareas simples donde esas habilidades no se usan.
3. **Falta de reusabilidad y mantenimiento:** Permite desacoplar el conocimiento operativo en paquetes versionables y reutilizables entre distintos agentes y proyectos en vez de duplicar prompts monstruosos .

**Técnicas clave (Estructura agnóstica de una Skill):**

- **Catálogo mínimo (** **Catalog / Trigger Metadata** **):** Exponer en el contexto global únicamente el nombre y un desencadenante claro (cuándo usarla y cuándo no), ocupando menos de 100 tokens. *Ejemplo:* `{"name": "analisis_pdf", "description": "Usar solo cuando el usuario adjunte balances financieros en PDF para extraer tablas contables"}`.
- **Carga bajo demanda (** **Progressive Disclosure / Dynamic Context Injection** **):** Inyectar el cuerpo del procedimiento (`instructions.md` o archivo de guía) solo en la vuelta del bucle agéntico donde el modelo decide activar la habilidad. *Ejemplo:* Si el agente llama a `load_skill("analisis_pdf")`, el middleware lee el archivo local y añade las reglas de extracción al contexto.
- **Aislamiento de herramientas (** **Scoped Toolsets** **):** Asociar herramientas y permisos específicos a la skill para que el agente no tenga disponibles 50 herramientas a la vez, sino solo las 2 o 3 necesarias para esa tarea. *Ejemplo:* Mientras la skill de análisis contable esté activa, el agente solo tiene acceso a `extraer_tablas_pdf()` y no a `enviar_email()` o `escribir_db()`.
- **Offloading a scripts locales (** **Execution offloading** **):** Delegar tareas deterministas complejas (como parsear un CSV grande o formatear datos) a un script de Python ejecutable en disco en vez de hacer que el LLM lo razone token por token. *Ejemplo:* La skill incluye un archivo `scripts/parse_balance.py` que el agente corre por consola, trayendo solo el resultado procesado.

**La trampa o error común:** 

La **descripción ambigua y el solapamiento de habilidades**. Escribir descripciones genéricas como *"sirve para procesar datos"* o *"ayuda con archivos"* provoca que el router del agente no sepa qué skill activar, active múltiples skills a la vez saturando el contexto, o intente usar una skill para tareas que se resolvían con un prompt común. La regla fundamental es que cada skill debe tener límites negativos explícitos: definir con absoluta precisión **cuándo NO usarla** y delegar a la skill únicamente tareas que requieran un procedimiento estructurado de múltiples pasos o herramientas específicas.
