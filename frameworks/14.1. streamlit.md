**Qué es en criollo:**

 Es un framework que convierte **scripts de Python en aplicaciones web interactivas sin necesidad de tocar una sola línea de HTML, CSS o JavaScript**. Funciona bajo un modelo reactivo lineal: cada vez que el usuario interactúa con un widget en pantalla (toca un botón, mueve un slider o escribe un mensaje), Streamlit **vuelve a ejecutar todo tu script de Python de arriba a abajo**, actualizando la interfaz automáticamente en el navegador.

**Qué problema resuelve:** 

Resuelve la **fricción y lentitud de construir interfaces de usuario para prototipos, demos y herramientas internas en Python**. Elimina tres barreras críticas:

1. **La brecha Frontend/Backend:** Permite que un AI Engineer o Data Scientist publique un MVP o demo interactivo en minutos sin tener que aprender React, configurar bundlers, lidiar con CSS o armar APIs intermedias.
2. **Validación rápida con usuarios y negocio:** Facilita testear flujos de prompts, parámetros de RAG o agentes directamente con usuarios no técnicos mediante controles visuales (sliders, inputs, botones de chat) en lugar de una terminal o una notebook estática.
3. **Visualización inmediata de datos y medios:** Conecta de forma nativa la salida de código Python (tablas de datos, gráficos, mapas, respuestas de LLM con streaming o audio) a componentes renderizados en el navegador con una sola instrucción.

**Ejemplo mínimo y comandos base:**

```python
# uv add streamlit 
# uv run streamlit run app.py

import streamlit as st

# --- TEXTO Y TÍTULOS ---
st.title("Título principal")  # Título grande H1
st.header("Subtítulo")  # Encabezado H2
st.subheader("Sección")  # Encabezado H3
st.write("Texto común o datos")  # Imprime texto, diccionarios, dataframes o variables

# --- INPUTS DE USUARIO ---
texto = st.text_input("Etiqueta")  # Campo para escribir texto corto
archivo = st.file_uploader("Subí tu archivo", type=["csv", "pdf", "txt"])
area = st.text_area("Mensaje largo")  # Campo para párrafos o prompts
numero = st.number_input("Número", 0, 100)  # Entrada numérica
slider = st.slider("Selector deslizable", 0, 10)  # Slider con rango
opcion = st.selectbox("Elegí uno", ["A", "B"])  # Menú desplegable
tilde = st.checkbox("Acepto términos")  # Casilla de verificación (True/False)
boton = st.button("Ejecutar")  # Botón que devuelve True al cliquear

# --- MENSAJES DE ESTADO / ALERTAS ---
st.success("Operación exitosa")  # Caja verde de confirmación
st.warning("Cuidado con esto")  # Caja amarilla de advertencia
st.error("Ocurrió un error")  # Caja roja de fallo
st.info("Dato informativo")  # Caja azul de información

# --- ESTRUCTURA Y LAYOUT ---
st.sidebar.write("Barra lateral")  # Manda cualquier elemento al panel izquierdo
col1, col2 = st.columns(2)  # Divide la pantalla en columnas
tab1, tab2 = st.tabs(["Pestaña 1", "Pestaña 2"])  # Separa contenido en solapas

```

**La trampa o error común:** 

Olvidar el **modelo de re-ejecución total (** **rerun** **) y el manejo del estado**. Al interactuar con cualquier widget, Streamlit vuelve a correr el script entero de arriba a abajo. Si guardás variables en variables comunes de Python (`contador = 0` o `mensajes = []`), se van a reiniciar a cero en cada clic. Para persistir datos entre interacciones tenés que usar obligatoriamente `st.session_state`. 

La segunda trampa crítica derivada de esto es **recalcular tareas pesadas en cada rerun**: si cargás un modelo, hacés un embedding o leés un archivo pesado sin cachear (usando `@st.cache_data` o `@st.cache_resource`), tu aplicación se congelará varios segundos cada vez que el usuario mueva un simple botón o slider.
